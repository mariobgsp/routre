Full Windows steps in the next section. Or let your AI do it — AI prompt below.

Self-update built in: routre update verifies sha256 and atomically replaces the binary. Old routre-cli installs still work (alias). npm distribution is deprecated.

Windows

No installer, no admin rights. One zip, one folder, one PATH entry.

Option A — manual (2 min)
# 1. Download the zip for your CPU from Releases:
#    https://github.com/mariobgsp/routre/releases/latest
#    routre_windows_amd64.zip  (Intel/AMD)  or  routre_windows_arm64.zip  (ARM)

# 2. Unzip to a permanent folder:
Expand-Archive .\routre_windows_amd64.zip -DestinationPath $HOME\routre

# 3. Add to PATH for this user (no admin):
$dir = "$HOME\routre"
[Environment]::SetEnvironmentVariable("Path", $env:Path + ";$dir", "User")
$env:Path += ";$dir"   # also for this shell

# 4. Setup + run:
routre version
routre setup --detect   # writes config.json + routre.env (0600) next to the exe
routre serve            # gateway + dashboard at http://127.0.0.1:20128/ui

# Verify:
curl http://127.0.0.1:20128/healthz   # → ok
routre check            # validates config + keys
routre list             # providers + savings + BUDGET HIT
Option B — PowerShell one-liner (auto PATH) 
irm https://raw.githubusercontent.com/mariobgsp/routre/main/install.ps1 | iex
# (falls back to manual zip if ps1 is not yet published — same 3 steps above)

Notes

SmartScreen may warn on first run — click More info → Run anyway (binary is unsigned, sha256-verified on update). Windows Defender: no Python/Postgres/Node, just one exe (~11 MiB, ~10 MiB RAM).

Run at startup

routre start --autostart registers a Scheduled Task (logon trigger). routre stop --autostart removes it. No service install, no admin.

Alias: routre.exe still launches the same binary. Config lives next to the exe: config.json + routre.env.
